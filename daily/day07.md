## 三、核心面试八股文

### 1. SysTick与TIM的区别

SysTick是Cortex-M内核的24位定时器，通常用于系统时基。

TIM是STM32外设定时器，可用于定时中断、PWM输出、输入捕获等功能。

对于20ms的普通舵机软件调度，可以使用HAL_GetTick()实现非阻塞控制；对于更严格的定时要求，可以使用TIM提供稳定的调度触发。

### 2. HAL_GetTick()的原理

STM32 HAL默认使用SysTick提供1ms时基。

SysTick中断调用HAL_IncTick()递增计数器，HAL_GetTick()读取当前Tick。

超时判断：

```c
if ((uint32_t)(now - last_tick) >= interval_ms)
{
    // 到达更新间隔
}
```

利用无符号减法的模运算特性，可处理正常的32位Tick回绕。

### 3. 为什么不推荐HAL_Delay()控制运动？

HAL_Delay()会阻塞当前执行流程，使主循环不能及时处理STOP或其他业务事件。

解决方法是使用非阻塞状态机：

- 主循环持续运行。
- 根据Tick判断是否需要更新。
- 每次调用只推进一轮运动。
- 其他时间处理通信和故障事件。

注意：非阻塞状态机不等于底层I²C完全非阻塞。

### 4. 什么是Jitter？

Jitter是实际任务执行时间相对于预期时间的偏差或波动。

例如，计划每20ms更新，但I²C同步通信占用了额外时间，实际调度间隔就可能出现波动。

解决思路：

- 减少主循环中的阻塞操作。
- 记录实际执行时间。
- 测试最坏执行时间。
- 对严格实时任务考虑硬件定时器和异步通信。

### 5. STOP能立即打断I²C写入吗？

不能保证。

UART中断可以接收STOP，但如果主循环正在执行同步I²C写入，需要等待调用返回后才能处理停止逻辑。

STOP通过取消后续轨迹实现软件停止；最后成功写入的目标角度不等于物理舵机的真实位置。

## 七、重要工程结论

### 1. 多通道写入不是原子操作

前两路成功、第三路失败时，已成功下发的命令不能自动回滚。

因此应立即停止后续运动控制，并记录故障状态。

### 2. 软件角度不等于实际位置

current_angles记录的是软件认为已成功下发的角度，不是舵机编码器反馈。

没有位置传感器时，无法仅凭软件数据证明物理位置。

### 3. 非阻塞与实时性不同

非阻塞调度可以避免整段运动持续占用主循环，但同步I²C调用仍可能阻塞。

### 4. 初始化不一定清除FAULT

测试时应防止FAULT状态污染后续用例，不能为了测试通过随意重置生产模块的保护状态。
