## 一、Cortex-M异常机制

### 1. 异常与中断
- Exception包括系统异常和外部IRQ。
- Cortex-M响应异常时，硬件通常自动保存R0～R3、R12、LR、PC和xPSR。
- 异常返回时根据EXC_RETURN恢复执行上下文。

### 2. NVIC
- NVIC负责中断使能、优先级管理与嵌套。
- 优先级数值越小，优先级越高。
- 抢占优先级决定中断嵌套，子优先级影响同抢占级待处理中断的响应顺序。

### 3. HardFault
常见原因：
- 非法地址访问。
- 栈溢出导致非法内存访问。
- 非法指令。
- 其他异常升级。

排查方法：
1. 检查CFSR、HFSR等故障状态寄存器。
2. 根据有效位检查BFAR、MMFAR。
3. 查看异常栈帧中的PC、LR。
4. 使用Keil反汇编、调用栈和寄存器窗口定位问题。

## 二、UART DMA与STOP响应

实际调用链：

UART DMA → HAL_UARTEx_RxEventCallback → 软件环形缓冲区 → uart_line_rx_poll → hand_protocol_parse_frame → ACK/seq检查 → hand_servo_start_action(STOP)。

核心知识：
- DMA负责接收，不代表命令立即处理。
- UART中断优先级高，不代表STOP业务执行优先。
- 同步I²C操作可能推迟主循环处理STOP。
- STOP软件响应延迟需要独立测量。

## 七、STOP响应延迟测试设计

计划使用三个时间点：

## 八、今日面试标准表达

**为什么DMA收到STOP仍可能延迟？**

DMA负责接收数据，但STOP还需要主循环解析和执行，同步I²C操作可能导致处理延迟。

**为什么提取UART模块？**

为了实现通信数据处理与业务控制解耦，提高代码复用性、可维护性及单元测试能力。

**为什么NVIC高优先级不能解决全部延迟？**

NVIC控制中断响应优先级，但主循环中的阻塞操作仍可能延迟业务逻辑执行。

**为什么需要完整链路测试？**

编译和组帧测试只能验证部分功能，响应时间必须通过真实软件调用链测量。
